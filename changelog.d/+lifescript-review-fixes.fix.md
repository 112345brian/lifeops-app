LifeScript now resolves a bare identifier inside nested `all()`/`any()` quantifiers against the innermost bound element first, instead of letting an outer element's same-named field win. Numbers reaching the engine as any `java.lang.Number` (`Byte`, `BigDecimal`, a JSON decoder's own lazy number type) or a Kotlin unsigned type are coerced like every other number rather than silently comparing unequal, and a `null` smuggled into a context or element map raises a LifeScript error instead of escaping as null or a raw NullPointerException. Quantifier and parse errors also read better: an unknown set name says when no sets were provided at all and otherwise lists the ones that were, and an empty string literal is no longer reported as "end of input".
