Wired the on-device YNAB read-decide-write pipeline: `LifeOpsComputeWorker`'s tick now fetches unapproved transactions directly from YNAB, runs `YnabEngine`'s categorize/approve/hold/cover decision logic, resolves novel payees via `AnthropicClient.categorizeUnknownPayee`, and writes the result back with YNAB PATCH calls — self-gated once/day, with no biometric prompt (matches the unattended, background-automation behavior of the existing server-side `run_ynab`). No retry wrapper was added around the writes since YNAB's transaction/category PATCH is idempotent, unlike FlowSavvy's non-idempotent creates.
